================================================================================
  EXECUTIVE SUMMARY
================================================================================

ARGUS is a state-of-the-art multi-agent debate framework with rigorous Bayesian
reasoning, full provenance tracking, and a unique adversarial architecture.
However, a comparative analysis against leading simulation and prediction systems
— particularly MiroFish, OASIS, Stanford Generative Agents, ChatEval, AutoGen,
MetaGPT, CAMEL, and Swarms — reveals eight architectural gaps that limit ARGUS
to static, single-session, small-scale debates on hand-crafted propositions.

This document specifies eight novel extensions to ARGUS that close all identified
gaps while preserving the existing debate flow entirely. Every extension is
designed as an opt-in Python module that plugs into the existing RDCOrchestrator
without breaking changes. Together they transform ARGUS from a point-in-time
claim verifier into a living, self-improving epistemic intelligence platform.

The extensions are not incremental improvements — each introduces at least one
algorithmic innovation that does not exist in any current open-source or research
system. They are designed to be shippable individually as pip-installable
sub-packages under the argus-debate-ai namespace, allowing phased delivery and
independent versioning.

- Stanford Generative Agents (foundational agent memory architecture)

ROOT CAUSES IN CURRENT ARGUS ARCHITECTURE:

1. Static Posteriors
   C-DAG has no timestamped evidence decay. Every evidence node has equal
   temporal weight regardless of when it was produced. A 2018 meta-analysis
   carries the same weight as a 2025 RCT.

2. 4-Agent Ceiling
   Moderator, Specialist, Refuter, Jury are hard-coded roles. No concept of
   agent population, no peer-to-peer communication mesh, no emergent behavior
   possible at any scale.

3. Manual Proposition Input
   No document-to-proposition pipeline. Users must hand-craft clean propositions
   with explicit priors. Raw reports, articles, or news are not ingestible.

4. Stateless Agents
   No memory backend. No expertise that evolves. No calibration tracking across
   sessions. Each debate starts as if no prior debates occurred.

5. Flat Debate Architecture
   No hierarchical decomposition. A complex multi-dimensional proposition is
   debated as a single claim, producing poor evidence coverage and low-quality
   verdicts.

6. Verdict as Endpoint
   No forward inference from verdict. ARGUS tells you what the evidence says
   but not what follows from that verdict — no consequence reasoning.

7. No Cross-Session Knowledge
   No persistent registry of past verdicts. Related prior debates produce no
   benefit to new debates on semantically related claims.

8. Static Evidence Only
   Evidence is ingested pre-debate. No mechanism to consume new evidence
   arriving mid-debate from live streams or APIs.

────────────────────────────────────────────────────────────────────────────────
  01. CHRONOS — Temporal Belief Drift Engine
────────────────────────────────────────────────────────────────────────────────

PROBLEM STATEMENT
-----------------
ARGUS produces a single scalar posterior for a proposition — a snapshot of what
the evidence says right now. But propositions exist in time. Evidence from five
years ago may have been superseded. Drug efficacy claims, policy assessments, and
financial propositions all have beliefs that should drift as evidence ages.

No existing multi-agent debate system models time as a first-class dimension of
belief. CHRONOS introduces the first Temporal C-DAG and a suite of algorithms
for tracking, visualising, and explaining belief change over time.

CORE INNOVATION: Evidence Half-Life & Belief Drift Detection
------------------------------------------------------------
Every evidence node in the CHRONOS Temporal C-DAG carries a decay_function — a
parametric curve that reduces its effective confidence as time passes. The decay
rate is evidence-type-specific:

  EMPIRICAL (RCT data)     : half-life ~5 years
  MARKET signals           : half-life ~24 hours
  EXPERT opinion           : half-life ~2 years
  STATISTICAL analysis     : half-life ~3 years

The Bayesian posterior is computed as a TemporalPosterior — a time-indexed
series of posterior estimates with Bayesian credible intervals.

The key novel algorithm is the Belief Drift Detector. It identifies inflection
points in the posterior curve and automatically traces back through the C-DAG to
identify which evidence cluster caused each shift. This closes a critical
explainability gap: CHRONOS tells you not just THAT belief changed, but precisely
WHICH evidence caused it and WHEN.

ALGORITHM: Evidence Decay Function
-----------------------------------
  temporal_weight(e, t) = confidence(e) * decay_fn(e.type, age(e, t))

  decay_fn(type, age):
    EMPIRICAL   -> exp(-lambda_e * age)   # lambda_e = ln(2) / 5y
    MARKET      -> exp(-lambda_m * age)   # lambda_m = ln(2) / 1d
    EXPERT      -> exp(-lambda_x * age)   # lambda_x = ln(2) / 2y
    STATISTICAL -> exp(-lambda_s * age)   # lambda_s = ln(2) / 3y

  log_odds_t = logit(prior) + Sum_i( temporal_weight(e_i, t) * log(LR_i) )
  posterior_t = sigmoid(log_odds_t)

ALGORITHM: Belief Drift Detector
---------------------------------
Runs PELT (Pruned Exact Linear Time) change-point detection on the
TemporalPosterior series. For each detected inflection point, identifies evidence
nodes whose temporal_weight changed most sharply in the surrounding window.
Creates a causal attribution: "Belief shifted from 0.64 to 0.41 on [date]
primarily due to [evidence node] losing confidence weight as it aged."

  class BeliefDriftDetector:
      def detect_inflections(self, temporal_posterior: TemporalPosterior)
          -> list[InflectionPoint]

      def trace_cause(self, inflection: InflectionPoint, cdag: TemporalCDAG)
          -> CausalAttribution   # {evidence_id, delta_weight, impact_score}

      def generate_drift_report(self, prop_id: str) -> BeliefDriftReport
          # Returns: timeline, inflections, causal attributions, summary prose

API DESIGN
----------
  from argus.chronos import ChronosOrchestrator, EvidenceHalfLifeRegistry

  registry = EvidenceHalfLifeRegistry(
      empirical_years=5.0,
      market_hours=24.0,
      expert_years=2.0,
      statistical_years=3.0,
  )

  orchestrator = ChronosOrchestrator(
      base=rdc_orchestrator,
      half_life_registry=registry,
      temporal_resolution='month',  # day / week / month / year
      lookback_years=5,
  )

  result = orchestrator.debate(
      proposition='Drug X reduces mortality by >15%',
      prior=0.5,
      evidence_timestamps={'ev-001': '2020-03-01', 'ev-002': '2024-11-15'},
  )

  print(result.temporal_posterior.at('2022-01'))   # 0.712
  print(result.temporal_posterior.at('2025-01'))   # 0.583
  print(result.drift_report.inflections)
  print(result.drift_report.causal_attributions)

────────────────────────────────────────────────────────────────────────────────
  02. PHALANX — Population-Scale Epistemic Simulation
────────────────────────────────────────────────────────────────────────────────

PROBLEM STATEMENT
-----------------
ARGUS's 4 hard-coded agents cannot reveal emergent consensus phenomena —
polarisation, false consensus, minority dissent, and herding effects that only
emerge when hundreds of independent perspectives interact. The 4-agent verdict is
a small committee's opinion, not a population-level belief distribution.

PHALANX wraps the existing RDCOrchestrator with a population layer. It spawns N
EpistemicPersona instances — each a lightweight virtual analyst with a distinct
cognitive prior, domain expertise weighting, and a set of active cognitive biases.
These personas run parallel micro-debates using the existing CRUX protocol, and
their aggregate beliefs form a PopulationPosterior — a full distribution over
possible verdicts rather than a single point estimate.

CORE INNOVATION: Cognitive Bias Engine
---------------------------------------
The CognitiveBiasEngine assigns each persona a randomised set of cognitive biases
— quantified as numerical weight modifiers applied during evidence evaluation.

  Confirmation bias  : increases weight of evidence aligned with persona's prior
  Anchoring bias     : applies inertia factor resisting large posterior updates
  Availability bias  : amplifies weight of recent/vivid evidence
  Authority bias     : boosts weight of evidence from high-prestige sources
  Recency bias       : over-weights the most recent evidence

These biases are NOT simulated symbolically — they are implemented as
differentiable weight functions applied directly to the CRUX Dialectical Fitness
Score computation. This makes PHALANX the first multi-agent debate system to
model cognitive bias as a first-class numeric component of reasoning.

The EmergentConsensusDetector analyses the PopulationPosterior for structural
features: bimodality (genuine controversy), high variance (high uncertainty),
skew (asymmetric evidence), and the Polarisation Index.

ALGORITHM: Cognitive Bias Weight Modulation
--------------------------------------------
  class CognitiveBias(Enum):
      CONFIRMATION  = 'confirmation'
      ANCHORING     = 'anchoring'
      AVAILABILITY  = 'availability'
      AUTHORITY     = 'authority'
      RECENCY       = 'recency'

  def apply_bias(evidence, persona, bias) -> float:
      base_weight = evidence.confidence * evidence.relevance
      if bias == CONFIRMATION:
          alignment = cosine(evidence.embedding, persona.prior_embedding)
          return base_weight * (1 + persona.bias_strength * alignment)
      if bias == AVAILABILITY:
          recency_score = 1 / (1 + days_since(evidence.date))
          return base_weight * (1 + persona.bias_strength * recency_score)
      if bias == ANCHORING:
          delta = abs(posterior - persona.initial_prior)
          inertia = exp(-persona.bias_strength * delta)
          return base_weight * inertia
      return base_weight

ALGORITHM: Polarisation Index
-------------------------------
  def polarisation_index(population_posterior: PopulationPosterior) -> float:
      # Split population into top and bottom quartile by belief
      q1 = population_posterior.quartile(0.25)   # pessimist cluster
      q4 = population_posterior.quartile(0.75)   # optimist cluster

      # Jensen-Shannon Divergence between the two sub-distributions
      # PI = 0 means consensus, PI = 1 means complete polarisation
      pi = jsd(q1.distribution, q4.distribution)
      return pi

  Interpretation:
    PI < 0.1   -> Strong consensus
    PI 0.1-0.3 -> Moderate disagreement
    PI > 0.5   -> Genuine controversy — single verdict is unreliable

API DESIGN
----------
  from argus.phalanx import PHALANXOrchestrator, PHALANXConfig

  config = PHALANXConfig(
      population_size=500,
      bias_sampling='empirical',     # empirical / random / custom
      parallel_workers=16,
      consensus_threshold=0.1,
  )

  orchestrator = PHALANXOrchestrator(base=rdc_orchestrator, config=config)
  result = orchestrator.debate('The intervention is cost-effective', prior=0.5)

  # Standard verdict (unchanged)
  print(result.verdict.label)              # 'SUPPORTED'
  print(result.verdict.posterior)          # 0.73

  # PHALANX-specific outputs
  print(result.population_posterior.mean)  # 0.69
  print(result.population_posterior.std)   # 0.14
  print(result.polarisation_index)         # 0.31  <- moderate controversy
  print(result.consensus_type)             # 'CONTESTED'
  print(result.minority_dissent_clusters)  # [DissentCluster(size=87, belief=0.31)]

────────────────────────────────────────────────────────────────────────────────
  03. SEED — Structured Evidence Extraction & Debate-Priming
────────────────────────────────────────────────────────────────────────────────

PROBLEM STATEMENT
-----------------
ARGUS requires users to hand-craft clean propositions and load context documents
manually. Real analysts have a research report, news article, or policy document
— not a LaTeX-formatted claim with confidence priors. The manual proposition-
crafting step is the biggest usability barrier and the largest gap versus systems
like MiroFish that accept raw seed material.

SEED is an end-to-end pipeline that ingests any document (PDF, HTML, plain text,
Markdown, JSON) and automatically:
  1. Extracts candidate propositions
  2. Scores them for debate-readiness (DebatabilityScore)
  3. Pre-builds a C-DAG skeleton populated with evidence fragments
  4. Outputs a DebateReadyBundle that plugs directly into RDCOrchestrator

The analyst goes from raw document to running debate in a single line of code.

CORE INNOVATION: DebatabilityScore
------------------------------------
The DebatabilityScore is a novel composite metric that quantifies how suitable
an extracted claim is for structured debate.

  DebatabilityScore = w1*BiPolarityRatio + w2*NoveltyQuotient + w3*EvidenceDensity

  BiPolarityRatio  = min(pos_signals, neg_signals) / max(pos_signals, neg_signals)
                     # 1.0 = perfectly balanced, 0.0 = all one-sided

  NoveltyQuotient  = 1 - max_cosine_similarity(claim, verichain_claims)
                     # 1.0 = completely novel, 0.0 = already well-established

  EvidenceDensity  = count(relevant_chunks) / total_chunks  (capped at 1.0)

  Interpretation:
    Score > 0.7  -> Excellent debate candidate
    Score 0.4-0.7 -> Good debate candidate
    Score < 0.4  -> Low-value; filter out

PIPELINE STAGES
---------------
  Stage 1: Document Ingestion
    Loads PDF/HTML/TXT/Markdown/JSON. Runs OCR if needed. Extracts raw text
    with structural metadata (sections, headings, captions).
    Output: Raw text + metadata

  Stage 2: Claim Mining
    LLM-powered extraction of candidate propositions using structured prompting.
    Identifies declarative claims, quantified assertions, comparative statements.
    Output: List[RawClaim]

  Stage 3: Entity Linking
    Links entities in claims to knowledge graph nodes (Wikipedia, Wikidata).
    Resolves abbreviations, acronyms, and domain-specific terms.
    Output: List[LinkedClaim]

  Stage 4: Debatability Scoring
    Computes BiPolarityRatio, NoveltyQuotient, EvidenceDensity per claim.
    Ranks and filters claims by composite DebatabilityScore.
    Output: List[ScoredClaim]

  Stage 5: Evidence Pre-population
    For top-N claims: extracts supporting/opposing chunks from source document.
    Builds C-DAG skeleton with pre-classified evidence polarity.
    Output: CDAG skeleton

  Stage 6: Bundle Assembly
    Packages proposition, pre-built CDAG, evidence index, prior estimate.
    Output: DebateReadyBundle (plugs directly into RDCOrchestrator)

API DESIGN
----------
  from argus.seed import SEEDOrchestrator, SEEDConfig

  seed = SEEDOrchestrator(
      llm=get_llm('openai', model='gpt-4o'),
      config=SEEDConfig(
          max_claims=20,
          top_claims=3,
          min_debatability=0.4,
          enable_entity_linking=True,
          prior_estimation=True,
      )
  )

  bundle = seed.from_file('research_paper.pdf')   # From PDF
  bundle = seed.from_text(article_text)           # From raw text
  bundle = seed.from_url('https://example.com/')  # From URL

  for claim in bundle.ranked_claims:
      print(f'{claim.text[:80]}  [Score: {claim.debatability_score:.2f}]')

  # Run debate on top claim — zero additional setup
  result = rdc_orchestrator.debate_bundle(bundle.top_claim)

----------------

────────────────────────────────────────────────────────────────────────────────
  04. MNEME — Persistent Agent Memory & Expertise Evolution
────────────────────────────────────────────────────────────────────────────────

PROBLEM STATEMENT
-----------------
Every ARGUS debate starts from a blank slate. The Specialist agent that processed
200 clinical trial papers last week retains nothing of that experience. Agents
never develop domain expertise, never improve their calibration, and cannot recall
evidence they have already evaluated.

MNEME is a pluggable memory layer that adds persistent, evolving memory to every
ARGUS agent without changing any existing API. It introduces three memory stores
per agent:

  1. KnowledgeReservoir  : vector store of evaluated evidence with recency decay
  2. ExpertiseProfile    : domain competence scores updated via Bayesian rules
  3. CalibrationHistory  : per-agent accuracy tracking over time

CORE INNOVATION: Calibration Drift Monitoring
----------------------------------------------
The CalibrationDriftMonitor tracks not just whether agents are accurate, but
whether their accuracy is IMPROVING or DETERIORATING over time, and specifically
identifies the domains where calibration has degraded.

Mechanism:
  - Rolling window Brier Score computed per domain per agent
  - When drift detected above configurable threshold, MNEME automatically
    adjusts the agent's credibility weight in future debates
  - Poorly-calibrated agents become less influential — without human intervention

No existing agent memory system (Zep, MemGPT, or other) tracks calibration drift
as a first-class metric or uses it to auto-adjust agent influence.

MEMORY ARCHITECTURE
-------------------
  # KnowledgeReservoir: semantic memory of evaluated evidence
  reservoir.store(evidence_node, outcome=True, debate_id='d-001')
  related = reservoir.retrieve('treatment efficacy RCT', top_k=10, decay=True)

  # ExpertiseProfile: domain competence with Bayesian updates
  profile.update('clinical', prediction=0.75, actual=True)
  print(profile.competence('clinical'))   # 0.82  <- improved
  print(profile.competence('finance'))    # 0.51  <- near-baseline

  # CalibrationHistory: rolling Brier Score per domain
  history.record('clinical', predicted_prob=0.75, outcome=True)
  drift = history.detect_drift('clinical', window=30)
  print(drift.direction)    # 'DEGRADING'
  print(drift.magnitude)    # 0.08  <- significant
  print(drift.adjustment)   # -0.15 <- credibility weight reduction

MEMORY BACKEND OPTIONS
----------------------
  SQLiteMemoryBackend    : Local / development (SQLite file on disk)
  PostgreSQLMemoryBackend: Production / team (PostgreSQL + pgvector)
  QdrantMemoryBackend    : High-volume / research (Qdrant vector DB)
  InMemoryBackend        : Testing / ephemeral (Python dict, no persistence)

API DESIGN
----------

────────────────────────────────────────────────────────────────────────────────
  05. FRACTAL — Hierarchical Proposition Decomposition
────────────────────────────────────────────────────────────────────────────────

PROBLEM STATEMENT
-----------------
Real-world questions are multi-dimensional. "Is autonomous vehicle technology
commercially viable by 2030?" contains dozens of implicit sub-claims spanning
safety, regulation, battery technology, infrastructure, and consumer acceptance.
Running a flat debate on this top-level proposition produces a low-quality verdict
because the evidence is too mixed and too broad.

FRACTAL automatically decomposes a complex proposition into a PropositionTree —
a directed acyclic graph of sub-propositions at multiple abstraction levels.
ARGUS runs debates in parallel on all leaf nodes. Results propagate up the tree
using HierarchicalBayesianAggregation, accounting for the logical relationship
between each sub-proposition and its parent.

CORE INNOVATION: Logical Relationship Classifier
-------------------------------------------------
The LogicalRelationshipClassifier automatically classifies how each sub-
proposition relates to its parent:

  NECESSARY    : Parent requires child to be true
                 If child is false, parent MUST be false
                 Aggregation: logical AND (product of posteriors)

  SUFFICIENT   : Child alone implies parent
                 If child is true, parent is likely true regardless of others
                 Aggregation: logical OR (1 - product of complements)

  CONTRIBUTING : Child increases parent probability but is neither necessary
                 nor sufficient
                 Aggregation: weighted Bayesian update

  INDEPENDENT  : Child is an orthogonal dimension of the parent's truth
                 Aggregation: geometric mean (orthogonal evidence combination)

This relationship-aware aggregation does not exist in any current reasoning,
debate, or hierarchical planning system.

ALGORITHM: Hierarchical Bayesian Aggregation
---------------------------------------------
  def aggregate_children(parent_node, children, relationships) -> float:
      necessary    = [c for c,r in zip(children, relationships) if r == NECESSARY]
      sufficient   = [c for c,r in zip(children, relationships) if r == SUFFICIENT]
      contributing = [c for c,r in zip(children, relationships) if r == CONTRIBUTING]
      independent  = [c for c,r in zip(children, relationships) if r == INDEPENDENT]

      # NECESSARY: parent false if any necessary child is false
      p_necessary = product(c.posterior for c in necessary) if necessary else 1.0

      # SUFFICIENT: parent true if any sufficient child is true
      p_sufficient = 1 - product(1-c.posterior for c in sufficient) if sufficient else 0.0

      # CONTRIBUTING: weighted Bayesian combination
      p_contributing = bayesian_combine([c.posterior for c in contributing],
                                         [c.weight for c in contributing])

      # INDEPENDENT: geometric mean (orthogonal evidence)
      p_independent = geometric_mean(c.posterior for c in independent) if independent else 0.5

      return combine_components(p_necessary, p_sufficient, p_contributing, p_independent)

API DESIGN
----------
  from argus.fractal import FRACTALOrchestrator, FRACTALConfig

  fractal = FRACTALOrchestrator(
      base=rdc_orchestrator,
      config=FRACTALConfig(
          max_depth=3,
          max_children=5,
          min_leaf_complexity=0.3,
          parallel_workers=8,
      )
  )

  result = fractal.debate('Is autonomous vehicle technology viable by 2030?')

  # Root verdict
  print(result.root_verdict.posterior)   # 0.58
  print(result.root_verdict.label)       # 'UNCERTAIN'

  # Full proposition tree
  result.tree.visualize()  # Exports interactive HTML tree

  # Per-leaf verdicts
  for node in result.tree.leaves:

────────────────────────────────────────────────────────────────────────────────
  06. MIRROR — Consequence Inference Graph
────────────────────────────────────────────────────────────────────────────────

PROBLEM STATEMENT
-----------------
ARGUS produces a verdict on a proposition — but says nothing about what follows
from that verdict. Real decision-making requires understanding consequences: "If
this drug IS effective, what else is implied? Which protocols should change? What
does it mean for competing treatments?"

MIRROR is a post-debate inference engine that takes a completed verdict and
generates a ConsequenceGraph — a forward-inference DAG of propositions that
logically follow from the verdict. Each consequence node receives:

  ConsequenceProbability : probability that consequence holds given parent verdict
  SensitivityScore       : how much consequence probability changes if verdict shifts

CORE INNOVATION: Counterfactual Challenger
-------------------------------------------
After building the full consequence graph, CounterfactualChallenger runs a
pivotality analysis: for each consequence node, it computes the partial derivative
of ConsequenceProbability with respect to the root verdict's posterior.

The node with the highest sensitivity is identified as the PIVOTAL CONSEQUENCE —
the outcome most dependent on the root verdict being correct.

CounterfactualChallenger then generates a structured counterfactual argument:
"If the root verdict were reversed (posterior from 0.73 to 0.27), consequence X
would shift from high probability to low probability. This implies [decision
impact]."

This sensitivity-to-root-verdict analysis applied to a consequence chain is a
completely original technique.

ALGORITHM: Consequence Probability
------------------------------------
  def consequence_probability(consequence_node, parent_verdict) -> float:
      p_given_true  = consequence_node.conditional_prob_given_true
      p_given_false = consequence_node.conditional_prob_given_false
      p_parent = parent_verdict.posterior
      return p_given_true * p_parent + p_given_false * (1 - p_parent)

  def sensitivity_score(consequence_node, parent_verdict) -> float:
      # dP(consequence) / dP(parent) — first-order sensitivity (central difference)
      delta = 0.01
      p_plus  = consequence_probability(node, posterior=parent_verdict.posterior + delta)
      p_minus = consequence_probability(node, posterior=parent_verdict.posterior - delta)
      return (p_plus - p_minus) / (2 * delta)

----------

      )
  )

────────────────────────────────────────────────────────────────────────────────
  07. VERICHAIN — Cross-Debate Truth Network
────────────────────────────────────────────────────────────────────────────────

PROBLEM STATEMENT
-----------------
Every ARGUS debate starts with a blank slate, as if all prior reasoning never
happened. If ARGUS already established "Treatment X is effective in Phase 3
trials" last month, a new debate on "Treatment X reduces symptoms by 20%" should
know this and use it as strong prior evidence. Currently it does not.

VERICHAIN is a persistent, cryptographically signed registry of all ARGUS
verdicts across sessions. Each verdict is stored as a TruthNode — a versioned,
signed, hash-linked record. When a new debate begins, the VERICHAINRetriever
queries the registry for semantically related prior verdicts and injects them as
high-credibility evidence nodes into the new C-DAG automatically.

CORE INNOVATION: Epistemic Precedent Scoring
---------------------------------------------
The EpistemicPrecedentScorer computes a PrecedentScore for each prior verdict
cited in a new debate. Inspired by academic citation analysis — treating past AI
reasoning as citable intellectual authority.

  def precedent_score(truth_node: TruthNode, registry: VERICHAINRegistry) -> float:
      citation_count  = registry.count_citations(truth_node.verdict_id)
      citation_weight = log(1 + citation_count) / log(1 + registry.max_citations)

      version_penalty = 1.0 if not truth_node.is_superseded else 0.2

      confidence_weight = truth_node.verdict.posterior
      if truth_node.verdict.posterior < 0.5:
          confidence_weight = 1 - truth_node.verdict.posterior  # flip for 'false' verdicts

      return (0.4 * citation_weight) + (0.3 * version_penalty) + (0.3 * confidence_weight)

  High-PrecedentScore verdicts -> injected as near-expert-quality evidence
  Low-PrecedentScore verdicts  -> excluded or downweighted

TRUTH CHAIN INTEGRITY
----------------------
Each TruthNode is hash-linked to prevent tampering:

  TruthNode:
    verdict_id    : UUID
    proposition   : str
    verdict       : VerdictResult
    posterior     : float
    timestamp     : ISO8601
    session_id    : str
    prev_hash     : SHA256  (hash of preceding TruthNode)
    node_hash     : SHA256  (SHA256(prev_hash || verdict_data))
    signature     : HMAC    (cryptographic attestation)
    version       : int     (incremented on supersession)
    superseded_by : Optional[UUID]

────────────────────────────────────────────────────────────────────────────────
  08. PULSE — Live Evidence Stream Processor
────────────────────────────────────────────────────────────────────────────────

PROBLEM STATEMENT
-----------------
All evidence in ARGUS is static — loaded before the debate begins and frozen for
its duration. For rapidly evolving topics — financial decisions, breaking news,
clinical trial monitoring — new evidence may arrive mid-debate that completely
changes the picture. ARGUS has no mechanism to consume this evidence or
incorporate it without restarting the debate.

PULSE connects ARGUS to live data streams (RSS feeds, news APIs, academic preprint
servers, financial data APIs) and routes incoming evidence to active debates in
real-time. A NoveltyDetector filters out semantically redundant incoming evidence.
An UrgencyRouter uses the existing VoI planner to estimate how much incoming
evidence would shift the current posterior, and routes accordingly.

CORE INNOVATION: Posterior Interrupt Protocol (PIP)
----------------------------------------------------
When the UrgencyRouter determines that incoming evidence has a Value of
Information above a configurable threshold, PIP:

  1. Pauses the current debate round at the nearest safe checkpoint
  2. Injects the new evidence as an EMERGENT evidence node
     (a new EvidenceType introduced specifically for stream-sourced evidence)
  3. Triggers an immediate targeted Refuter pass on the new evidence alone
  4. Resumes the debate from the checkpoint

The interrupt-resume semantics are non-destructive:
  - C-DAG is append-only during an interrupt
  - Bayesian posterior is updated incrementally
  - Provenance ledger records the interrupt event with full attribution

Interrupt-driven live evidence injection into an ongoing Bayesian debate chain
does not exist in any existing reasoning system.

ALGORITHM: UrgencyRouter VoI Classification
--------------------------------------------
  class UrgencyRouter:
      def classify(self, evidence, active_debate) -> RoutingDecision:
          # Step 1: Novelty gate
          novelty = self.novelty_detector.score(evidence, active_debate.index)
          if novelty < self.min_novelty_threshold:
              return RoutingDecision.DISCARD

          # Step 2: VoI estimate
          voi = self.voi_estimator.estimate(evidence, active_debate.current_posterior)

          # Step 3: Route by urgency
          if voi > self.interrupt_threshold:
              return RoutingDecision.INTERRUPT
          elif voi > self.queue_threshold:
              return RoutingDecision.QUEUE_NEXT
          else:
              return RoutingDecision.QUEUE_FUTURE

STREAM CONNECTOR ARCHITECTURE
------------------------------
  RSSConnector           : Any RSS / Atom feed, configurable polling
  NewsAPIConnector       : NewsAPI.org, near real-time, keyword/domain filtering
  ArXivStreamConnector   : arXiv new submissions, daily batch, category filtering
  FinancialStreamConnector: Yahoo Finance / Alpha Vantage, tick-level (rate limited)
  PubMedStreamConnector  : PubMed new publications, daily batch, MeSH term filtering
  CustomWebhookConnector : Any HTTP endpoint, push-based, custom filter function
